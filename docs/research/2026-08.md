# 2026-08 maintenance sweep

First sweep since the tool shipped. Tested against Claude Code 2.1.220 on macOS.

## Transcript format

Unchanged. Still the record we write.

Checked every transcript under `~/.claude/projects` modified in the last 30 days.
The only title record type present is `custom-title`, 2070 of them, with the same
three keys we emit in `src/transcript.js:129`:

```json
{"type":"custom-title","customTitle":"...","sessionId":"..."}
```

No new title record type appeared, and no variant spelling. `ai-title`, which
`titleInfo` also reads, did not show up in the sample, but the reader costs
nothing to keep.

The official docs still do not document the title record at all. `.claude`
directory reference describes `projects/<project>/<session>.jsonl` only as the
full conversation transcript. Third-party writeups of the format state plainly
that entry shapes are internal and can change between releases. So the empirical
check above stays the method for this sweep, not the docs.

## Session title API

A title tool now exists, but it does not replace the JSONL append.

`ccd_session_mgmt` gained `set_session_title(session_id, title)`. It is exposed
to agents inside the desktop app. Two constraints decide the question for us:

1. Its own schema says the target "must not be the current session". Our Stop
   hook titles the session it is running in, which is exactly the excluded case.
2. It is an in-agent MCP tool, not a CLI surface. `claude-session-namer` runs as
   a CLI process and a hook, neither of which can call it.

There is a third constraint we already know from this machine: the desktop rename
path silently refuses agent renames of `titleSource: user` sessions.

The upstream request to expose a rename tool to agents, anthropics/claude-code
issue 75733, is still open, which suggests the shipped tool is not considered the
general answer either. Nothing to act on. Keep watching for a CLI flag or a
self-rename allowance, since either would change the calculus.

Adjacent and mildly useful: since 2.1.101, `claude -p --resume <name>` accepts
session titles set via `/rename` or `--name`. Titles this tool writes become
resume handles. Worth a README line eventually, not urgent.

## Headless behavior

This is the one actionable finding.

2.1.81 added `--bare`, described in `claude --help` on 2.1.220 as minimal mode
that skips hooks, LSP, and plugin sync. We do not use it. Our two headless call
sites are `src/settings.js:162` (auth probe) and `src/titler.js:256` (the title
call).

Measured on this machine, `claude -p 'say ok' --model haiku`, alternating:

| run | normal | `--bare` |
|-----|--------|----------|
| 1   | 8.43s  | 1.48s    |
| 2   | 11.82s | 1.40s    |

Roughly 7x, and it confirms what we assumed: the per-call cost is CLI startup,
not the model. Backfill is the obvious beneficiary, since its 10 to 20 seconds
per session is the same startup paid once per session. It would also make the
`--concurrency` idea in the V2 list much less necessary, because most of what
concurrency was going to hide is startup that `--bare` removes outright.

Skipping hooks is a benefit rather than a cost here. Our worker calls should not
be firing the user's Stop hook, and the worker already has to recognize and
refuse its own sessions.

Before adopting, two things need checking, neither done in this sweep because it
does not touch code:

- whether `--bare` changes stdout shape at all, since `titler.js` parses what
  comes back
- whether bare worker runs still leave session files behind. Four probe runs
  produced no titled transcript in this project directory, but nine transcripts
  across all projects were touched in the same window, so this is not settled.

## Hooks

Several new events since launch: `TaskCreated` (2.1.120, also 2.1.84),
`StopFailure` (2.1.78), `PreCompact` blocking via exit code 2 (2.1.105), a
`defer` permission decision for `PreToolUse` (2.1.90), and `duration_ms` on
`PostToolUse` inputs (2.1.119). 2.1.101 fixed `SessionStart` hooks firing twice
on `--resume`.

None of these affect us. We use `Stop` and it is unchanged. `StopFailure` is the
only one worth a thought later: it fires when a turn ends on an API error, which
is a case we currently just do not title. That is the correct behavior, so there
is nothing to change.

## Competing tools

Both known competitors are dormant.

- **claude-rename** (sathwick-p/claude-rename): last push 2026-04-07, 11 stars,
  not published to npm. Its final commit, cleaning up `claude -p` worker sessions
  so they never appear in `/resume`, is the same pollution problem noted in the
  headless section above. Worth reading before we adopt `--bare`.
- **claude-chat-namer**: npm 1.0.0, last modified 2026-03-19. No release since
  before we launched.

One new entrant: a "Rename Session" skill listed on mcpmarket, which renames
sessions by ID without resuming them. It is a manual labeling tool, so it does
not overlap with automatic titling.

No new automatic session-titling tools found on npm or GitHub this sweep. The
README's framing of how this tool differs still holds.

## Our issues

github.com/sturimcode/claude-session-namer has zero issues, open or closed.
Nothing matching a silent format change, which agrees with the format check above.

## Summary

One thing to act on: adopt `--bare` for headless calls, measured at roughly 7x
faster startup, biggest effect on backfill. Verify stdout shape and worker
session cleanup first.

Everything else is watch only. Format unchanged, no usable title API, no
competitive pressure.
